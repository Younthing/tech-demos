# Replica Run — PLAN

## Goal (one sentence)

Run the [replica-skill](https://github.com/Jakeschincariol/replica-skill) pipeline (MIT, Jake Schincariol) end to end on one small public web app — **Pomofocus** (https://pomofocus.io, a free browser Pomodoro timer) — and ship a clean-room, rebranded replica called **Ripen** together with the pipeline's two most interesting outputs: the **replica-diff parity scorecard** and the **replica-entrepreneur "complaints → selling points"** list, all inside one local Bun app.

## Why this target

- Tiny surface (one main screen, a task list, a settings modal, a report view), so a full recon → build → diff loop fits in one demo.
- Publicly reachable with no login for the core flow, so recon and same-viewport layout screenshots of the original are possible from public pages only.
- Has public user feedback reachable through sanctioned sources (Hacker News Algolia API ≈ 18 hits for "pomofocus", Reddit official JSON/search, Product Hunt pages read like a person). The sample will be small — the report must say so.

## Clean-room rules (non-negotiable, from the skill)

- Rebuild **what it does, never what it owns**: features and flows only. Never copy its source, CSS, JS bundles, logo, icons, sounds, copy text or images. Write every line fresh.
- Brand: name **Ripen**, own palette (not Pomofocus red `#ba4949`/teal/blue mode colours), own icon (lucide or an original SVG), own wording. Do not use "Pomofocus" or "pomofocus.io" anywhere in the product UI; the name appears only on the case-study pages (diff / fixes / about) as the factual subject of the study.
- `replica-brand/sweep.py` must pass over `src/` (the product) with `--avoid "Pomofocus" --domains pomofocus.io --colors "#ba4949,#38858a,#397097"`; case-study data files are excluded and listed in `replica/brand.json`.
- Entrepreneur: **never fabricate** reviews, quotes, ratings or counts. Every quote verbatim, with its URL; sample size stated. Reading, not scraping: only the HN Algolia API, Reddit's official endpoints within terms, and manual reading. If a source cannot be reached, say so. Reviewer quotes are research, never shown as testimonials for Ripen.
- Layout diff compares structure only (imgdiff layout mode); colour differences are intended.

## Single-user MVP

One local web app, `bun install && bun run dev`, three routes:

1. **`/` — Ripen (the replica).** Focus / short break / long break modes; start, pause, skip; configurable durations, auto-start, long-break interval; task list (add, edit, estimate pomodoros, mark done, active task shown under the timer, est. finish time); end-of-session sound (synthesised with Web Audio, no copied asset) and browser notification; tab title countdown; keyboard shortcut for start/pause; everything persisted to `localStorage`; a simple report (today's focus minutes and completed pomodoros). Own palette per mode.
2. **`/diff` — replica-diff scorecard.** Renders `replica/parity.json` (generated by the vendored `parity.py` from `replica/features.csv`) and the per-screen layout scores from `imgdiff.py --json`: overall score (80% features + 20% layout), feature score, must-haves done / total, per-area bars weakest first, missing list in build order, behaviour-diff table, side-by-side original vs Ripen screenshots with the diff image, and the verdict (not shippable / shippable / better than the original).
3. **`/fixes` — complaints → selling points.** Renders `replica/feedback.json` (from the vendored `reviews.py`) and `replica/fixes.md`: the three lists (what they hate / what is missing / what is unsolved) each with counts, sources, thin-theme badges and linked verbatim quotes; the 5–8 item fix plan (S/M/L, status in Ripen); the three positioning angles with the recommended one. Each fix that Ripen ships is marked and linked back to the feature row (`original = no`).

Plus a small **`/about`** panel: the 11-step pipeline (recon → … → deploy), which steps were run here and which were skipped (backend, launch, deploy — out of scope for a local demo), with links to each artifact in `replica/`.

### Explicitly out

- Accounts, sync, payments, Todoist-style integrations, premium features of the original (marked `skip` with a reason in `features.csv`).
- replica-backend, replica-launch, replica-deploy (listed as skipped on `/about`).
- Any server, database or paid API at runtime. No LLM calls at runtime.
- Mobile app; pixel parity.

## Tasks (vertical slices, in order)

1. **Scaffold.** `apps/replica-run/bunfig.toml` with `[install] minimumReleaseAge = 259200` first. Then `bunx create-vite@latest . --template react-ts` (no install), `bun install`, Tailwind v4 + `bunx shadcn@latest init` (neutral/minimal preset). Add components on demand (button, card, tabs, dialog, input, switch, progress, badge, table, separator). `react-router` for the four routes.
2. **Vendor the skill.** Copy the eleven `replica-*` folders' SKILL.md files and the Python tools (`parity.py`, `imgdiff.py`, `reviews.py`, `themes.json`, `sweep.py`, `contrast.py`) into `apps/replica-run/vendor/replica-skill/` with its MIT `LICENSE` and a README noting the source commit. Python 3.8+ stdlib only — used at authoring time, not at runtime.
3. **Recon.** Write `replica/recon.md` (screens S01…, flows, components, data model) and `replica/features.csv` (feature, area, priority, original, clone, notes) from the public site and its public FAQ section only. Save original screenshots at 1440x900 and 390x844 to `replica/screens/` (used only for the diff — never shipped in the product UI as Ripen assets).
4. **Architect + design.** `replica/architecture.md` (client-only, localStorage schema), `replica/tokens.json` with Ripen's own palette; run `contrast.py` and keep its output.
5. **Build Ripen (`/`).** Core flow first: timer + modes + task list, then settings, sound/notification, report. Tick `clone` column in `features.csv` as you go.
6. **Test.** `replica/test-plan.md` from the flows; Playwright e2e for the core flow (start → finish focus → auto break → task pomodoro counted) plus unit tests for the timer reducer. Bugs in `replica/bugs.md`.
7. **Diff.** Clone screenshots to `replica/clone-screens/` at the same viewports/states; run `imgdiff.py --json` per screen and `parity.py --visual … --markdown > replica/parity.md`; also emit JSON for the UI (`bun run replica:diff` wraps these). Write the behaviour-diff table honestly.
8. **Entrepreneur.** Collect real feedback into `replica/reviews.csv` (source,url,date,rating,text) via HN Algolia API + Reddit + manual reading; edit `themes.json` for timer apps (e.g. timer drift in background tabs, sound, ads/premium, sync, task UX). Run `reviews.py` → `replica/feedback.md` and JSON; write `replica/fixes.md`; add fix rows to `features.csv` with `original = no`; implement 2–3 of the S-sized fixes in Ripen (e.g. drift-free timing based on timestamps, not intervals).
9. **Brand.** `replica/brand.md` + `brand.json` (name, palette, voice, logo brief); run `sweep.py` on `src/` and keep a clean result.
10. **Case-study pages.** `/diff`, `/fixes`, `/about` reading the JSON/MD artifacts at build time (Vite `import`), so the app needs no server.
11. **Media + PR.** Screenshots of `/`, `/diff`, `/fixes` and an original-vs-Ripen comparison; one screen recording (timer running, task added, mode switch, then the diff and fixes pages). Attach to the PR.

## Structure

```
apps/replica-run/
  PLAN.md  README.md  bunfig.toml  package.json  vite.config.ts  components.json
  vendor/replica-skill/        # MIT, upstream SKILL.md files + python tools
  replica/                     # pipeline artifacts (recon, features.csv, tokens, parity, reviews, fixes, brand, screens)
  scripts/replica-diff.sh      # runs imgdiff + parity, writes replica/*.json
  src/
    app/        (router, layout, nav)
    features/timer/   (Ripen: timer reducer, modes, settings, sound, notifications)
    features/tasks/   (task list)
    features/report/
    features/case-study/  (diff, fixes, about pages)
    components/ui/   (shadcn)
  tests/  e2e/
```

## Stack (one line each)

- **Bun** — runtime, package manager, scripts (repo rule).
- **Vite + React + TypeScript** (`bunx create-vite`) — boring, fast, enough for a client-only multi-page demo; Next.js would be framework weight with no server need.
- **react-router** — four routes, nothing more.
- **Tailwind v4 + shadcn/ui (minimal)** — repo default UI.
- **Vendored replica-skill Python tools** — the actual skill's scoring/ranking, so numbers come from the tool, not hand-written.
- **Vitest + Playwright** — reducer unit tests and one core-flow e2e.

## Testing / hooks

- Unit: timer reducer (mode transitions, long-break interval, timestamp-based remaining time). Unit: task pomodoro counting.
- E2E: one Playwright core-flow test (with fake clock).
- No git hooks beyond what the scaffold ships.

## Deferred

- Accounts/sync, launch page, deploy — not needed to show the pipeline; listed as skipped.
- More review sources (App Store/Play have no listing for this web app) — the sample size is reported as is.
- Re-evaluate after the first slice (timer + diff page) runs.
